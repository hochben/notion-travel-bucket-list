# Travel map

A self-updating world map of the destinations in my Notion **Destinations** database.
It is embedded at the top of my Notion *Travel Bucket List* page.

Nothing here needs to be rebuilt by hand, and there is no CI in this repository.
A Notion agent called **Travel Map Sync** watches the database and writes `data.json`
here directly, using its own GitHub connection. The map reads that file.

```
Notion database  ->  Travel Map Sync agent  ->  data.json  ->  the map embedded in Notion
```

The agent runs when a destination is created, when Status / Budget / Continent changes,
when a destination is deleted, and once an hour as a safety net. Each run writes the
complete list, so any drift is repaired by the next run. It commits only when the file
would actually change.

## Files

| File | What it is |
| --- | --- |
| `data.json` | Generated by the agent. Destination name, status, budget, continent and ISO 3166-1 numeric country codes. Do not edit by hand. |
| `codes.json` | Destination name -> country codes. Fallback for destinations with no codes set in Notion. |
| `index.html` | Standalone copy of the map, for serving over GitHub Pages. |

There is deliberately no `NOTION_TOKEN` secret and no GitHub Action. An earlier design
pulled from the Notion API on a schedule; it was replaced by the agent push, and its
workflow and build script have been deleted.

## How a destination gets onto the map

Country shapes are keyed by ISO 3166-1 numeric codes, so each destination needs at least
one code. Codes come from, in order:

1. A **Map countries** text property on the Notion page, e.g. `276`, or `32, 152` for a trip
   spanning two countries. Preferred: a brand new destination maps itself with no change to
   this repository.
2. `codes.json`, keyed by exact destination name.

A destination with neither is listed in `data.json` under `unmapped` instead of quietly
vanishing.

Destinations with status **In Review** are deliberately excluded - they are drafts.
Approving one flips it to *Want to go*, which is when it appears on the map.

## Notes

- Country outlines are fetched from the public `world-atlas` package on a CDN, with two
  fallback hosts.
- The map tries several sources for `data.json` in order: this repository on
  `raw.githubusercontent.com`, then jsDelivr.
- The map keeps a baked-in copy of the last known data. If every source fails it shows that
  instead of an empty map, and labels itself an offline copy. If you ever see "offline copy"
  in the footer, the map could not reach `data.json` - the data itself is not the problem.
- This repository moved from a personal account into the `benhoch-dev` organisation. Old
  `hochben/...` URLs still redirect, but browsers refuse redirected cross-origin fetches, so
  anything fetching `data.json` must use the `benhoch-dev` URL.
